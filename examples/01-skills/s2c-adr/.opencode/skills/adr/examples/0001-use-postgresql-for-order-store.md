# 0001. 주문 저장소로 PostgreSQL을 사용한다

- 상태: Accepted
- 날짜: 2026-02-03
- 결정자: 주문 서비스 팀

## 맥락

주문 서비스는 주문, 결제 상태, 배송 상태를 한 트랜잭션으로 갱신해야 한다. 정산 팀이 주문 데이터를 임의 조건으로 집계하는 쿼리를 자주 요청하고, 스키마는 분기마다 한두 번 바뀐다.
팀 5명 중 4명이 PostgreSQL 운영 경험이 있고, 문서 저장소(NoSQL) 운영 경험은 없다.

## 결정

우리는 주문 서비스의 주 저장소로 PostgreSQL을 사용한다. 스키마 변경은 마이그레이션 파일로만 한다.

## 대안

| 대안 | 장점 | 단점 | 채택하지 않은 이유 |
| --- | --- | --- | --- |
| MongoDB | 스키마 변경이 유연하다 | 여러 문서에 걸친 트랜잭션이 번거롭다. 팀에 운영 경험이 없다 | 주문·결제의 원자적 갱신이 핵심 요구다 |
| MySQL | 팀 일부가 익숙하다 | 정산 팀의 집계 쿼리에 쓸 JSON·윈도 함수가 PostgreSQL보다 제한적이다 | 얻는 것이 PostgreSQL 대비 적다 |

## 결과

### 좋은 점

- 주문·결제·배송 갱신을 하나의 트랜잭션으로 처리한다.
- 정산 팀이 SQL로 직접 집계할 수 있다.

### 나쁜 점·감수할 것

- 스키마 변경 때마다 마이그레이션 작성과 리뷰가 필요하다.
- 쓰기 부하가 크게 늘면 수직 확장 이후에는 파티셔닝 설계가 필요하다.
