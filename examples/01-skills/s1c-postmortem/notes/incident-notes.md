# 장애 대응 메모 (가상의 사건 - 세미나 연습용)

주문 API 응답 지연. 채팅방 기록과 대시보드 메모를 그대로 붙여 둔 것이라 정리가 안 되어 있음.

## 채팅 기록 (2026-08-14, KST)

- 14:05 배포 담당자 A가 주문 서비스 v3.12 배포 완료. 주문 목록 조회에 "최근 주문 요약" 필드 추가한 릴리스.
- 14:20쯤 모니터링 화면에서 주문 API p95가 300ms -> 2.5s로 올라간 것을 당직자 B가 봤는데 배포 직후 흔한 일시적 현상이라 생각하고 넘김.
- 14:41 고객지원에서 "주문 내역이 안 열린다"는 문의 3건이 연달아 들어옴. 당직자 B가 그제서야 에러율 확인. 5xx 비율 18%.
- 14:46 인시던트 선언. 리드 C가 대응 책임자. 장애 채널 개설.
- 14:52 DB 대시보드에서 커넥션 풀 사용률 100% 확인. 대기 중인 요청이 쌓임.
- 15:03 슬로우 쿼리 로그에서 새 릴리스의 "최근 주문 요약" 쿼리가 주문 항목 테이블을 인덱스 없이 조인 중. 호출 한 번에 평균 4초.
- 15:10 롤백 vs 핫픽스 논의. 롤백이 더 빠르다고 판단.
- 15:18 v3.11로 롤백 시작. 15:26 롤백 완료.
- 15:31 풀 사용률 40%로 내려옴, 5xx 0.3%로 회복. 15:40 장애 종료 선언.
- 이후 확인: 14:05~15:26 사이 주문 목록 조회 요청 중 약 11%가 실패(약 4,200건). 결제 자체는 영향 없음(조회 API만 문제).

## 대시보드 메모

- 스테이징 DB에는 주문 데이터가 1만 건 정도라 이 쿼리가 빨랐음. 운영은 수천만 건.
- 배포 파이프라인에는 성능 테스트 단계가 없음.
- 풀 사용률 알림 기준은 없었음. 에러율 알림은 5분 평균 20% 이상이라 18%는 울리지 않음.
- 롤백 절차 문서가 있어서 헷갈리지 않고 진행함 (잘된 점).
- 인시던트 선언 후 상황 공유는 10분 간격으로 잘 지켜짐.
- 고객지원 -> 개발팀 에스컬레이션 경로가 오래 걸림. 문의 첫 접수는 14:30쯤이었다고 함.

## 후속 논의에서 나온 제안

- 주문 서비스 담당: 새 쿼리용 인덱스 추가 (D 담당, 이번 주 내)
- 플랫폼팀: 배포 파이프라인에 운영 규모 데이터로 하는 성능 테스트 단계 추가 (E 담당, 한 달 안)
- 모니터링 담당: 커넥션 풀 사용률 80% 알림, 에러율 알림 기준을 5% / 5분으로 (F 담당, 2026-08-21까지)
- 고객지원 운영: 오류 문의 3건 이상이면 개발 당직에게 바로 호출하는 규칙 (담당 미정)
- 배포 직후 30분은 p95 변화를 의무적으로 확인하는 체크리스트 (배포 담당)
