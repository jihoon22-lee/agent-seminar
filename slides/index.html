README.md

예제 폴더 하나하나가 그 자체로 opencode 프로젝트입니다. 해당 폴더로 들어가서 opencode를 실행하면 그 예제의 설정만 적용됩니다.

Linux에서 python 명령이 없으면 예제 설정의 python을 python3로 바꾸면 됩니다. README마다 적어 두었습니다.

에이전트는 코드를 잘 짭니다.
그런데 우리 팀은 모릅니다.

커밋 규칙, 리뷰 기준, 장애 티켓이 쌓인 시스템, 절대 하면 안 되는 명령.

모델은 인터넷 전체로 학습했지만, 우리 팀이 어제 정한 규칙이나 팀 안에만 있는 시스템은 알 수 없습니다.

opencode를 처음 보는 분을 위해

  • 터미널에서 쓰는 오픈소스 코딩 에이전트

opencode에는 확장 지점이 여럿 있습니다

확장 지점정체언제 쓰이나오늘
AGENTS.md, instructions항상 읽히는 프로젝트 규칙 문서모든 대화의 시작짧게
스킬폴더 + SKILL.md모델이 필요하다고 판단할 때중점
MCP 서버도구를 제공하는 별도 프로세스나 서버모델이 도구를 부를 때중점
플러그인opencode 안에서 도는 JS/TS 코드이벤트가 생길 때마다중점
permission설정으로 도구 사용 허용, 확인, 거부도구를 실행하기 직전짧게
명령, 에이전트/명령으로 부르는 프롬프트, 역할별 하위 에이전트사용자가 직접 고를 때다루지 않음

AGENTS.md는 항상 컨텍스트에 들어가므로 짧고 꼭 필요한 규칙만 둡니다. 길고 가끔 필요한 내용은 스킬로 빼는 것이 오늘의 첫 번째 요령입니다.

오늘은 가운데 세 줄이 주인공입니다. AGENTS.md와 스킬의 차이를 물어보시는 경우가 많은데, "항상 읽히나, 필요할 때만 읽히나"의 차이입니다.

스킬: 필요할 때 꺼내 보는 업무 매뉴얼

  • 폴더 하나에 SKILL.md가 들어 있으면 스킬이다
  • 머리말(frontmatter)의 description을 보고 모델이 쓸지 말지 판단한다
  • 본문에는 절차, 규칙, 예시를 쓴다
  • 필요하면 참고 문서, 템플릿, 스크립트를 같이 넣는다
  • 형식이 표준이라 다른 에이전트에서도 대부분 그대로 쓸 수 있다
.opencode/skills/ └─ commit-message/ ├─ SKILL.md 필수 ├─ references/ 필요할 때 읽을 문서 ├─ templates/ 결과물 틀 └─ scripts/ 실행할 코드
examples/01-skills/

스킬은 코드가 아니라 문서입니다. 모델이 읽고 따릅니다. 실행되는 무언가가 아니라는 점이 MCP, 플러그인과 가장 큰 차이입니다.

스킬은 세 단계로 나눠 읽힙니다

  1. 항상: 모든 스킬의 name과 description만 모델에게 보인다 스킬이 수십 개여도 부담이 작다
  2. 필요할 때: 모델이 skill 도구로 해당 스킬을 열면 SKILL.md 본문이 대화에 들어온다
  3. 더 필요할 때: 본문이 시키는 경우에만 references/ 문서를 읽거나 scripts/를 실행한다

그래서 description이 스킬의 전부입니다. 모델은 처음에 description만 보고 이 스킬을 쓸지 정합니다. 모호하게 쓰면 쓰이지 않습니다.

이 구조를 "점진적 공개"라고 부릅니다. 문서 전체를 매번 넣는 AGENTS.md와 달리, 정말 필요한 순간에만 비용을 냅니다.

description 작성법은 스킬 장에서 좋은 예와 나쁜 예로 실험한 결과를 보여 드립니다.

MCP: 에이전트에 도구를 꽂는 표준 규격

  • Model Context Protocol. 에이전트(클라이언트)와 도구 서버 사이의 약속
  • 서버는 별도 프로세스다. 어떤 언어로든 만들 수 있다
  • 서버가 줄 수 있는 것 세 가지
    • tools: 모델이 호출하는 함수 대부분 이것
    • resources: 읽을 수 있는 문서나 데이터
    • prompts: 미리 만든 프롬프트 틀
  • 표준이라 한 번 만든 서버를 여러 에이전트가 같이 쓴다

USB-C에 비유하면

기기(에이전트)와 주변기기(도구 서버)가 같은 단자 규격을 쓰기 때문에, 주변기기를 만드는 사람은 기기마다 따로 만들 필요가 없습니다.

티켓 시스템, DB, 팀 위키, 배포 도구처럼 에이전트 바깥에 있는 것에 손을 뻗게 해 줍니다.

MCP는 "능력"을 늘립니다. 스킬이 "어떻게 하라"는 지식이라면, MCP는 "이걸 할 수 있다"는 손발입니다.

속을 열어 보면 JSON 메시지를 주고받을 뿐입니다

  1. opencode가 서버를 시작하고 initialize로 인사한다
  2. tools/list로 도구 목록과 설명을 받는다
  3. 모델이 대화 중에 도구를 고른다
  4. opencode가 tools/call로 호출하고 결과를 모델에게 준다
examples/02-mcp/m1-stdio-minimal

SDK 없이 표준 라이브러리만으로 서버를 만들 수 있다는 것을 MCP 장에서 직접 보여 드립니다. 마법이 아니라 메시지 형식에 대한 약속이라는 점을 기억해 주세요.

플러그인: opencode 안에 끼워 넣는 코드

  • .opencode/plugins/에 JS/TS 파일을 두면 자동으로 로드된다
  • 정해진 훅에 함수를 걸어 두면 opencode가 때마다 부른다
  • 모델이 고르지 않는다. 조건이 맞으면 항상 실행된다
  • opencode 전용이다. 다른 에이전트로 옮길 수 없다
훅할 수 있는 일
tool.execute.before도구 실행 전 검사, 인자 수정, 차단
tool.execute.after실행 결과 기록, 후처리
shell.env셸 명령에 환경 변수 주입
event세션 종료, 권한 요청 같은 이벤트 수신
tool새 도구 추가
permission.ask, config, chat.*권한 판단, 설정 변경, 메시지 가공

플러그인은 "강제"입니다. 모델이 아무리 .env를 읽고 싶어 해도 플러그인이 막으면 못 읽습니다. 프롬프트로 하는 부탁과 다릅니다.
