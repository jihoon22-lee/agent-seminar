6

플러그인

모델이 무엇을 하든 항상 실행되는 코드: 막고, 기록하고, 주입하기

7분. 플러그인의 생김새, 훅이 불리는 순서를 보고 P1–P3을 봅니다(P4–P8은 심화). 데모는 P1(.env 차단).

플러그인은 훅을 돌려주는 함수입니다

  • .opencode/plugins/에 두면 자동 로드
  • 함수가 받는 것: client, project, directory, worktree, $(셸 실행)
  • 돌려주는 객체의 키가 훅 이름이다
  • throw하면 도구가 실행되지 않고 메시지가 모델에게 오류로 전달된다. 이유와 대안을 써 주면 모델이 그대로 따른다

파일에서 플러그인 함수만 export하세요. opencode는 export된 것을 모두 플러그인으로 부릅니다. 상수나 객체처럼 함수가 아닌 값이 하나라도 있으면 파일 전체가 로드되지 않고, 평소 화면에는 아무것도 안 나옵니다 (--print-logs에만 Plugin export is not a function). 보조 함수를 export하면 그 함수까지 플러그인으로 불립니다.

examples/03-plugins/p1-env-guard

export 함정은 실제로 한참 헤맨 부분입니다. 규칙 표를 테스트하려고 export const RULES를 붙였더니 플러그인이 통째로 사라졌는데, 평소 실행 화면에는 아무 표시가 없었습니다. opencode --print-logs로 실행하면 failed to load plugin 오류가 보입니다. import나 문법 오류는 그 로그에도 안 남으니, 로드될 때 파일에 한 줄을 남기게 해 두는 것이 가장 확실합니다. 이 레포의 플러그인은 logs/plugin-load.log에 한 줄을 씁니다.

before에서 예외를 던지면 권한 확인까지 가지 않고 끝납니다. 사용자에게 묻지도 않고, --auto로 실행해도 막힙니다. 반대로 after는 이미 실행된 뒤라 막을 수 없습니다. 기록과 후처리만 합니다.

before가 권한 확인보다 먼저입니다. 그래서 플러그인이 막으면 사용자에게 묻지도 않고 끝납니다. --auto로 실행해도 플러그인의 차단은 그대로입니다.

P1비밀 파일은 모델이 원해도 못 읽게

  • read, write, edit의 경로가 .env, .env.*이면 차단
  • bash의 cat .env, Get-Content .env 같은 우회도 차단
  • .env.example은 허용: 변수 이름은 알아야 일을 하니까
  • Windows 경로(C:\...\.env)도 처리

차단 35가지, 허용 24가지 사례를 node 단위 테스트로 고정했습니다. 1.19.5는 기본 권한으로도 .env 읽기 전에 묻습니다. 플러그인은 묻지 않고 거절하고, bash 우회와 --auto 실행까지 막습니다.

examples/03-plugins/p1-env-guard

이 출력은 실제 opencode를 실행했고, 어떤 도구를 부를지만 가짜 모델 서버가 정했습니다. 그래서 차단 동작은 매번 똑같이 재현됩니다. 실제 모델이 차단 뒤에 어떻게 반응하는지는 무료 모델 한도로 확인하지 못했습니다.

질문이 나올 만한 부분: opencode 1.19.5의 기본 권한에도 read의 *.env는 ask로 들어 있습니다(opencode debug agent build로 확인). 그래도 플러그인을 쓰는 이유는 승인 창 피로 없이 처음부터 거절하고, cat .env 같은 bash 우회도 막고, 모두 승인하는 --auto 실행에서도 그대로 동작하기 때문입니다. 정규식 가드라서 완벽한 차단은 아닙니다.

.env 읽기를 막는 플러그인

  1. 모델에게 .env를 보여 달라고 한다
  2. 로드 기록과 차단 기록을 본다
  3. TUI에서 bash로 우회해도 막히는지, 모델이 .env.example로 돌아가는지 본다
examples/03-plugins/p1-env-guard

P3에이전트가 한 일을 모두 남기기

  • tool.execute.after에서 한 줄씩 JSONL로 남긴다
  • 파일 내용과 비밀값은 남기지 않는다. 긴 문자열은 길이만, 토큰처럼 보이는 값은 가린다
  • 크기가 넘으면 파일을 돌려 쓴다 (rotation)
  • summarize_audit.py로 도구별 횟수와 타임라인을 본다
examples/03-plugins/p3-audit-log

"에이전트가 어젯밤에 뭘 했지?"에 답할 수 있어야 팀에서 안심하고 맡깁니다. 감사 로그는 모델과 상관없이 항상 남아야 하므로 플러그인의 일입니다.

P4작업이 끝나거나 승인이 필요할 때 알림

  • event 훅은 opencode의 모든 이벤트를 받는다
  • session.idle: 응답이 끝나고 입력을 기다린다
  • permission.asked: 도구 실행 전에 승인이 필요하다
  • Windows는 소리와 토스트, Linux는 notify-send 또는 터미널 벨

이벤트를 받아 외부 명령을 실행하는 구조는 발표자가 매일 쓰는 플러그인과 같습니다.

직접 부딪힌 함정

  • SDK 타입에는 permission.updated가 있지만 1.19.5는 permission.asked를 보낸다. permission.ask 훅은 한 번도 불리지 않았다. 타입보다 실제 이벤트를 기록해서 확인하자
  • opencode run은 끝나자마자 자식 프로세스를 정리한다. 알림은 TUI처럼 오래 떠 있는 opencode에서만 울린다
  • Windows에서 detached로 띄운 PowerShell은 아무것도 안 했다. cmd.exe /c start로 해결
examples/03-plugins/p4-notify-on-idle

모든 이벤트 이름을 파일로 남기는 진단 모드가 예제에 있습니다. 새 버전에서 이벤트 이름이 바뀌면 그걸로 확인하세요.

P5에이전트의 셸에만 환경 변수 넣기

  • 에이전트가 실행하는 셸에만 들어간다. 내 터미널과 시스템 환경은 그대로
  • 프록시, 사설 인증서 경로, 실행 환경 표시처럼 모두가 같아야 하는 값에 쓴다
  • bash 도구에만 적용된다. MCP 서버에는 environment 설정을 쓴다

Windows에서는 셸이 PowerShell이라 $APP_ENV는 빈 값, $env:APP_ENV로 읽어야 합니다. 그래서 예제는 python show_env.py로 확인합니다.

examples/03-plugins/p5-shell-env

"내 PC에서는 되는데 에이전트가 돌리면 프록시 때문에 안 된다" 같은 문제를 팀 단위로 없애는 용도입니다.

P6플러그인으로 모델이 부를 도구 만들기

  • MCP와 달리 이름에 접두사가 없다. 내장 도구 이름을 쓰면 내장 도구를 덮어쓴다
  • permission에 도구 이름으로 deny하면 모델에게서 사라진다
  • opencode 전용. 다른 에이전트에서도 쓰려면 MCP로
examples/03-plugins/p6-custom-tool

날짜 계산처럼 모델이 틀리기 쉬운 일을 코드로 고정할 때 좋습니다. 같은 프로세스에서 돌기 때문에 opencode SDK 클라이언트와 셸도 그대로 쓸 수 있습니다.

주의: 이 플러그인은 @opencode-ai/plugin을 import합니다. npm 레지스트리나 미러에 닿지 않으면 설치가 안 되고, 도구가 오류 없이 사라집니다. opencode --print-logs로 보면 background dependency install failed 경고가 있습니다.

P8플러그인을 팀에 나눠 주는 네 가지 방법

방법쓰는 때
(a) 프로젝트 .opencode/plugins/이 저장소 전용. 커밋하면 팀이 공유
(b) 전역 ~/.config/opencode/plugins/모든 프로젝트에 쓰는 개인 플러그인
(c) "plugin": ["./경로"]위치를 직접 정하거나 옵션을 넘길 때
(d) npm 패키지 "이름@1.2.0"여러 저장소에 버전 고정 배포. 레지스트리나 미러가 필요

같은 파일은 여러 번 적어도 한 번만 로드되지만, 같은 코드를 전역과 프로젝트에 둘 다 두면 두 번 실행됩니다. 감사 로그가 두 줄씩 찍힌다면 이것부터 보세요.

examples/03-plugins/p8-load-methods

demo.py는 모델 없이 시나리오마다 임시 폴더를 만들어 opencode를 실행하고, 플러그인이 남긴 마커 파일로 몇 번 로드됐는지 셉니다. npm 이름 형태(d3)는 예제에 들어 있는 작은 가짜 레지스트리로 오프라인에서 확인합니다.

P7대화가 압축돼도 잊으면 안 되는 것

대화가 길어지면 opencode가 앞부분을 요약(압축)합니다. 이때 experimental.session.compacting 훅으로 꼭 남길 사실을 요약 프롬프트에 덧붙입니다.

  • output.prompt를 넣으면 프롬프트 전체가 바뀌고 context는 무시된다
  • 훅이 예외를 던지면 압축 자체가 실패한다. 반드시 감싸서 실패를 삼킬 것
  • 압축은 TUI의 /compact, 서버 API, 또는 컨텍스트가 가득 찰 때 일어난다
  • 이름 그대로 실험적 훅이다. 버전이 바뀌면 다시 확인할 것
examples/03-plugins/p7-compaction-context

"이 프로젝트는 pnpm을 쓴다" 같은 사실이 압축 후에 사라져서 모델이 npm을 다시 쓰는 일이 있습니다. 그걸 막는 훅입니다. 요약 모델에게 사실이 전달되는 것까지는 확인했지만, 요약 결과에 실제로 남는지는 무료 모델 한도로 확인하지 못했습니다.
