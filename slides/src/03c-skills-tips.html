S5adescription 한 줄이 스킬의 운명을 정합니다

두 변형은 이 한 줄만 다르고 본문은 같습니다.

description 체크리스트

  • 무엇을 하는지 한 문장
  • 언제 쓰는지: 사용자가 실제로 칠 문장을 따옴표로
  • 팀 고유 단어(서비스명, 문서명)를 넣는다
  • 비슷한 스킬과 겹치면 "~에만 사용한다"로 선을 긋는다
  • 폴더 이름도 모델에게 보인다. 의미 있는 이름으로

compare.py가 같은 질문을 두 변형에 여러 번 던져 스킬이 열린 비율을 셉니다. 무료 모델 한도로 이번에는 수치를 얻지 못해, 직접 돌려 보는 실습으로 남겼습니다.

examples/01-skills/s5a-description-good-bad

실제 모델로 비율을 재는 compare.py가 있습니다. 결과는 모델과 날마다 달라집니다. 숫자보다 "description만 보고 고른다"는 구조를 기억해 주세요.

순서가 중요합니다. 나중에 쓴 규칙이 이깁니다. "deploy-*"를 먼저 쓰면 "*"가 덮어써서 막히지 않습니다.

방법1.19.5에서
머리말 disable-model-invocation: true효과 없음
permission.skill deny모델 목록에서 사라지고 호출도 거부. --auto로도 못 뚫음

examples/01-skills/s5b-manual-and-permission

다른 에이전트 문서에서 보던 disable-model-invocation은 opencode 1.19.5에서 아무 효과가 없었습니다. 수동 전용 스킬의 정답은 "permission으로 deny + 사람이 --command나 /skills로 부르기"입니다.

S5c팀에 스킬을 나눠 주는 방법과 함정

나눠 주는 방법

  • 프로젝트: .opencode/skills/에 넣고 코드와 함께 커밋
  • 팀 공용 저장소: 각자 clone하고 skills.paths로 가리킨다. git pull이 곧 배포
  • 정적 웹 서버: skills.urls에 index.json과 파일을 올린다

실험에서 드러난 함정

  • 같은 이름이 두 곳에 있으면 매번 이기는 쪽이 다르다 (로그에 "duplicate skill name"). 이름을 겹치지 않게
  • skills.paths의 상대 경로는 설정 파일이 아니라 opencode를 실행한 폴더 기준. 하위 폴더에서 실행하면 못 찾는다 → 절대 경로나 ~/
  • skills.urls는 version을 안 바꾸면 캐시를 계속 쓴다
examples/01-skills/s5c-scope-global-project

"전역보다 프로젝트가 이긴다"고 생각하기 쉬운데, 같은 이름 충돌은 경합이었습니다. 51번 중 2번은 반대로 나왔습니다. 이름을 겹치지 않게 짓는 것이 유일한 안전한 방법입니다.

스크립트를 시킬 때: Windows의 셸은 PowerShell입니다

opencode 1.19.5의 bash 도구는 Windows에서 Windows PowerShell 5.1로 실행됩니다. Git Bash가 설치돼 있어도 그렇습니다.

bash에서는 되지만PowerShell 5.1에서는
a && b문법 오류
$APP_ENV, export X=1$env:APP_ENV, $env:X="1"
date +%FGet-Date -Format yyyy-MM-dd
2>/dev/null, | head없음

스킬에 쓰는 명령은 두 셸에서 모두 도는 형태로.

python <스킬 폴더>/scripts/summarize_log.py logs/app.log처럼 명령 하나에 인자만 주는 형태가 가장 안전합니다. 경로 구분자는 /로 써도 Python이 처리합니다.

셸 문법이 필요한 일은 스크립트 안으로 옮기세요.

Linux 서버에서만 스킬을 만들면 Windows 사용자의 데모에서 터집니다. 이 레포의 모든 스킬은 두 셸에서 검증했습니다.
