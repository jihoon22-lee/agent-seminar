C6스킬과 헷갈리는 것: 내가 부르는 커스텀 명령

TUI에서는 /finish, 명령줄에서는 opencode run --command finish. 인자는 본문의 $ARGUMENTS, $1 자리에 들어간다.

스킬커스텀 명령
누가 부르나모델이 설명을 보고 고른다사용자가 /이름으로
부르기 전이름과 설명이 매 요청에 실린다 (예제: 103자)모델 요청에 아무것도 없다
부르면본문이 도구 결과로 들어온다본문이 내 메시지가 된다
알맞은 내용모델이 알아서 꺼내 써야 할 절차와 지식내가 매번 입력하던 지시문
examples/00-config/c6-custom-commands

같은 문장을 세 번째 입력하고 있다면 명령으로 만들 때입니다. "끝까지 진행해, 검사 통과하면 병합해, 문서도 고쳐" 같은 지시가 대표적입니다.

표의 내용은 가짜 모델이 받은 요청을 읽어서 확인했습니다. opencode.json의 command 키로도 정의할 수 있고, 같은 이름이면 md 파일이 이깁니다. 없는 명령 이름을 주면 Unexpected server error만 나오고 이름이 틀렸다는 말은 없습니다.

TUI에서 /finish로 부르는 동작은 이 자료를 만들 때 직접 확인하지 못했습니다. 발표 전에 한 번 해 보세요.

S5c팀에 스킬을 나눠 주는 방법과 함정

나눠 주는 방법

  • 프로젝트: .opencode/skills/에 넣고 코드와 함께 커밋
  • 팀 공용 저장소: 각자 clone하고 skills.paths로 가리킨다. git pull이 곧 배포
  • 정적 웹 서버: skills.urls에 index.json과 파일을 올린다

실험에서 드러난 함정

  • 같은 이름이 두 곳에 있으면 이기는 쪽이 보장되지 않는다. 대개 프로젝트가 이기지만 가끔 뒤집힌다 (로그에 "duplicate skill name"). 이름을 겹치지 않게
  • skills.paths의 상대 경로는 설정 파일이 아니라 opencode를 실행한 폴더 기준. 하위 폴더에서 실행하면 못 찾는다 → 절대 경로나 ~/
  • skills.urls는 version을 안 바꾸면 캐시를 계속 쓴다
examples/01-skills/s5c-scope-global-project

"전역보다 프로젝트가 이긴다"고 생각하기 쉬운데, 같은 이름 충돌은 경합이었습니다. 53번 중 2번은 반대로 나왔고, 6번 중 2번이 뒤집힌 날도 있었습니다. 이름을 겹치지 않게 짓는 것이 유일한 안전한 방법입니다.

스크립트를 시킬 때: Windows의 셸은 PowerShell입니다

opencode 1.19.5의 bash 도구는 Windows에서 Windows PowerShell 5.1로 실행됩니다. Git Bash가 설치돼 있어도 그렇습니다.

bash에서는 되지만PowerShell 5.1에서는
a && b문법 오류
$APP_ENV, export X=1$env:APP_ENV, $env:X="1"
date +%FGet-Date -Format yyyy-MM-dd
2>/dev/null, | head없음

스킬에 쓰는 명령은 두 셸에서 모두 도는 형태로.

python <스킬 폴더>/scripts/summarize_log.py logs/app.log처럼 명령 하나에 인자만 주는 형태가 가장 안전합니다. 경로 구분자는 /로 써도 Python이 처리합니다.

셸 문법이 필요한 일은 스크립트 안으로 옮기세요.

Linux 서버에서만 스킬을 만들면 Windows 사용자의 데모에서 터집니다. 이 레포의 스킬 예제는 가짜 모델이 정해진 명령을 부르게 해서 Windows PowerShell과 Linux bash 양쪽에서 check.py로 확인했습니다. 실제 모델이 어떤 명령을 만들지는 모델마다 다르니, 스킬에 "한 줄 명령만"을 적어 두는 것이 중요합니다.
