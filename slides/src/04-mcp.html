SDK 없이 서버를 만들고, 로컬에서 원격으로 옮기고, 실제 시스템에 붙이기

11분. M1에서 서버의 속을 보고, M4에서 원격으로 옮기고, M6에서 실제 시스템처럼 쓰는 모습을 봅니다. 데모는 M1, M4. M6 데모는 심화(시간이 남을 때).

서버가 할 일은 네 가지뿐입니다

  1. initialize에 답한다: 프로토콜 버전, 할 수 있는 일(capabilities), 서버 이름
  2. tools/list에 도구 목록을 준다: 이름, 설명, 인자 스키마
  3. tools/call을 실행하고 결과를 content로 돌려준다
  4. id가 없는 알림에는 절대 답하지 않는다. 모르는 알림은 조용히 무시한다
opencode 1.19.5가 실제로 보낸 것값
protocolVersion2025-11-25
clientInfoopencode 1.19.5
호출 뒤 알림notifications/cancelled
모델이 보는 도구 이름서버이름_도구이름
예: glossary_lookup_term
연결 제한 시간약 30초 (시작 + 도구 목록)
호출 제한 시간약 60초

표의 값은 예제 서버의 로그와 가짜 모델 서버로 직접 기록한 값입니다. 호출이 끝나면 opencode가 cancelled 알림을 보내는데, 여기에 답하면 안 됩니다. 4번 규칙이 실제로 중요한 이유입니다.

M1Python 표준 라이브러리만으로 만든 서버

  • stdin으로 한 줄 받고, stdout으로 한 줄 보낸다. 그게 stdio 전송의 전부다
  • 로그는 stderr로만 쓴다
  • Windows를 위해 입출력을 UTF-8로 맞춘다
  • 찾는 용어가 없으면 오류가 아니라 isError: true 결과로 돌려준다. 모델이 읽고 다시 시도할 수 있다

전체 파일은 주석이 많아 211줄이지만 실제 로직은 위가 전부입니다. SDK가 해 주는 일이 무엇인지 알고 쓰면 문제가 생겼을 때 훨씬 빨리 찾습니다.

M1모델은 도구의 설명을 보고 고릅니다

스킬의 description과 같은 원리입니다. 도구 설명은

  • 무엇을 하는지
  • 언제 쓰는지 (예시 단어 포함)
  • 다른 도구와 어떻게 이어지는지 "모를 때 먼저 사용한다"

를 담아야 합니다.

이 설명은 서버를 켜 두는 동안 매 요청마다 모델에게 전달됩니다. 길게 쓰면 그만큼 비용이 듭니다.

M3토큰과 경로는 환경 변수로 넘깁니다

실험해서 확인한 동작

  • 환경 변수가 없으면 빈 문자열로 바뀐다. 오류가 나지 않으니 서버가 직접 확인해야 한다
  • {file:}은 설정 파일 기준 상대 경로이고 앞뒤 공백을 지운다. 파일이 없으면 opencode가 시작을 거부한다
  • debug config는 키 이름으로 가린다. API_TOKEN, *_SECRET은 ***, TOKEN_PATH는 그대로 보인다

토큰이 없어서 도구가 거절당하자, 모델이 bash로 glossary.json을 직접 읽어 버렸습니다. MCP 서버의 인증은 파일 직접 접근을 막지 못합니다. 진짜 경계는 권한 설정이나 플러그인입니다.

examples/02-mcp/m3-env-config

마지막 경고는 실제 모델 실행에서 관찰한 것입니다. 데이터가 에이전트가 읽을 수 있는 곳에 있으면, 도구를 막아도 다른 길로 갑니다. 민감한 데이터는 원격 서버 뒤에 두는 이유이기도 합니다.

M4같은 서버를 HTTP로 띄워 원격으로 붙이기

  • 서버 쪽: POST로 JSON-RPC를 받아 JSON으로 답한다. 알림에는 202, GET에는 405
  • 토큰이 틀리면 401

고정 토큰이면 "oauth": false

  • 없으면 401을 받은 뒤 opencode가 OAuth 서버를 찾는 요청(/.well-known/..., /register)을 보낸다
  • 있으면 바로 SSE error: Non-200 status code (401)로 실패해 원인이 분명하다
  • 서버가 꺼져 있으면 SSE error: ECONNREFUSED

오류 문구가 "SSE"로 시작하는 건 opencode가 마지막에 SSE 방식으로 재시도한 결과를 보여 주기 때문입니다. GET에도 인증을 걸어야 진짜 원인(401)이 보입니다.

examples/02-mcp/m4-remote-http

로컬에서 원격으로 바꿀 때 서버 코드는 거의 그대로이고, 설정은 command가 url로 바뀝니다. 대신 인증과 오류 메시지 해석이 새로 생깁니다.

M5한 곳에 띄우고 팀이 함께 쓰는 서버

  • 팀원마다 다른 것은 환경 변수 두 개뿐
  • 토큰 = 사용자. 서버 로그에 누가 어떤 도구를 불렀는지 남는다
  • 도구를 고치면 서버만 다시 띄운다. 각자 PC에 배포할 것이 없다
examples/02-mcp/m5-team-shared-server

기본은 127.0.0.1에만 열립니다. 팀원이 접속하려면 --host 0.0.0.0으로 여는데, 이 예제는 HTTP라 토큰이 평문으로 갑니다. 사무실이나 VPN 안이 아니라면 앞에 HTTPS 리버스 프록시를 두고, 방화벽으로 팀 대역만 허용하세요.

tokens.json은 요청마다 다시 읽어서 재시작 없이 토큰을 교체할 수 있습니다. 대신 서버가 죽으면 모두가 못 씁니다.

M6내부 시스템을 붙인다면: 장애 티켓 DB

설계 원칙 세 가지

  • 최소 권한: DB를 ?mode=ro로 연다. SQLite가 쓰기를 거부한다. 모델이 SQL을 직접 쓰지 않는다
  • 작은 도구: search_tickets, get_ticket, ticket_stats 세 개만
  • 결과 크기 제한: 기본 10건, 최대 20건, 긴 문장은 120자에서 자른다

"지난주 payment 서비스 장애 티켓 요약해줘" → 모델이 기간과 서비스를 골라 호출한다.

examples/02-mcp/m6-sqlite-tickets (prepare.py가 가상 티켓 DB를 만든다)

실제 시스템이라면 SQLite 대신 팀의 실제 API나 DB가 들어가는 자리입니다. 원칙은 같습니다. 읽기 전용, 좁은 도구, 작은 결과.

모델에게 SQL 실행 도구를 통째로 주면 편하지만, 무엇을 할지 통제할 수 없고 결과가 커져 컨텍스트를 낭비합니다.
