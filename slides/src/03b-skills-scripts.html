스크립트가 붙으면: 계산은 코드가, 해석은 모델이

  • 모델이 스킬을 열면 opencode가 본문 끝에 스킬 폴더의 절대 경로와 파일 목록을 붙여 준다
  • 모델은 그 경로를 앞에 붙여 python <스킬 폴더>/scripts/x.py를 bash 도구로 실행한다
  • 작업 폴더는 그대로 프로젝트 루트다. 데이터 경로는 프로젝트 기준, 스크립트 경로는 스킬 폴더 기준
  • 스크립트는 결과를 짧은 요약(JSON, 표)으로 돌려준다. 원본 2,000줄 대신 요약 수십 줄이 컨텍스트에 들어간다

스크립트 경로를 SKILL.md에 절대 경로로 쓸 필요가 없습니다. opencode가 실행 시점의 위치를 알려 주므로 레포를 어디에 clone하든 그대로 동작합니다. Windows에서는 이 줄이 C:\…\log-analysis처럼 백슬래시 경로로 나옵니다.

  • 같은 커밋이면 매번 같은 분류. 목록을 스크립트가 만들므로 커밋이 빠지거나 섞이지 않는다

S3c커밋 전에 비밀값이 섞였는지 검사

  • 값은 앞 3글자와 길이만 보여 준다. 모델에게도 비밀값이 전달되지 않는다
  • 종료 코드 1 = 발견. 모델이 "괜찮다"고 말해도 숫자는 바뀌지 않는다
  • BUILD_ID는 git SHA일 수 있는 오탐 후보. 이걸 가려내 설명하는 것이 모델 몫

스킬에 넣을 스크립트를 만들 때

스크립트 쪽

  • 표준 라이브러리만. 설치 단계가 없어야 누구 PC에서나 돈다
  • 출력은 짧게. 원문 대신 요약, 필요하면 --sample N으로 일부만
  • 종료 코드로 성공, 발견, 오류를 구분 (0 / 1 / 2)
  • --help를 친절하게. 모델도 읽는다
  • 네트워크 없이 동작. 결과물에도 외부 링크를 넣지 않는다

SKILL.md 쪽

  • 실행할 명령을 그대로 적는다: python <스킬 폴더>/scripts/x.py 인자
  • "python이 없으면 python3" 한 줄 (Linux)
  • &&, 파이프, $변수 없이 한 줄. Windows에서는 PowerShell이 받는다
  • "하지 말 것"을 쓴다: 원본 전체 읽기, 스크립트 고치기, 숫자 지어내기
  • 스킬을 건너뛰고 grep부터 하는 모델도 있다. 데모 프롬프트에는 스킬 이름을 넣는다

S3a와 S3b를 만들 때 실제 모델이 스킬을 열지 않고 바로 grep, git log를 실행한 적이 있었습니다. description을 다듬는 것이 근본 대책이지만, 데모처럼 실패하면 안 되는 자리에서는 "log-analysis 스킬로"처럼 이름을 직접 말하는 편이 안전합니다.
